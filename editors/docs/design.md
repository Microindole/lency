# 编辑器设计与边界

## 定位

Lency 编辑器支持的目标是提供可用、可回归且边界清晰的开发体验。编辑器不是语言规范来源，也不应先于编译器创造新语义。

## 原则

- **LSP 优先**：类型、引用、重命名和语义诊断应由 `crates/lency_ls` 提供。
- **降级可见**：语言服务不可用时，状态栏必须明确显示 `Lency: Fallback`。
- **降级保守**：fallback 只提供文本级辅助和基础诊断，不假装具备完整语义精度。
- **行为可验证**：可观察行为变化必须有自动化回归，不依赖手工猜测。
- **与自举解耦**：当前仓库主线是 `lencyc/` 自举。编辑器可以展示 selfhost 的已稳定能力，但不得把 Rust 母体“可用”直接表述为 selfhost “可用”。

## 分层

```text
VS Code 扩展
    -> 语法高亮、片段、状态与 LSP 客户端
crates/lency_ls
    -> 语言服务协议与语义能力
Rust 母体 / Lency selfhost
    -> 语言事实与能力边界
```

TextMate、snippet 和 fallback provider 是客户端体验层，不得成为第三套语言实现。
