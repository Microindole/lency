# 模块

## 导入源码

导入路径使用点号分隔模块名。项目模块对应源码路径，标准库源码位于 lib/std。导入让当前文件能够引用模块提供的声明。

```lency
import std.str

int main() {
    var present = contains("Lency", "enc")
    if present {
        return 0
    }
    return 1
}
```

导入不是动态加载。最终构建仍需要编译相关源码，并满足被调用函数的类型和链接约束。

## 两套前端的导入形式

上例的单模块路径形式用于普通文档示例。母体的组合导入使用顶层大括号，也具有别名解析入口。

母体形式说明：

```text
import {
    std.io;
    std.io as my_io;
}
```

自举前端支持标准库模块列表与通配导入；通配形式仅面向标准库。

自举前端形式说明：

```text
import std.{io, fs, str}
import std.*
```

这些扩展形式不能当成两套前端已对齐的证据。新程序优先使用明确的单模块导入，避免依赖未经对应链路验证的别名或组合形式。

## 自举导入的检查边界

自举 resolver 会读取被导入模块并登记可见类型与函数签名。签名中的字段、参数、返回类型和泛型参数名称需要能在声明作用域中解析；同模块的类型前向引用有回归覆盖。

签名可导入不等于模块全部函数体均经过语义检查，也不等于泛型和完整标准库都可由自举后端生成。需要运行某项模块能力时，应参考对应的端到端回归；整体状态见[自举状态](../development/status.md)。
