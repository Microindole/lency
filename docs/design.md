# Lency 设计原则

## 定位

Lency 是一门面向日常程序开发的静态类型语言。它追求 C 系语言清晰的块结构和接近脚本语言的表达效率，但不以替代 C、C++ 或 Rust 的底层能力为目标。

最终目标是自举：使用 Lency 实现并构建 Lency 编译器。

## 核心原则

- **清晰**：语义应能从源码直接理解，拒绝要求读者模拟编译器推理的“黑魔法”。
- **显式**：避免隐式转换和不可解释的泛型推断；重要边界应出现在语法中。
- **默认安全**：空值必须显式进入类型，尽量在编译期阻止错误。
- **简洁**：避免 Java 式样板和无收益的抽象层级。
- **组合优先**：优先使用结构体、trait 和组合，而不是继承层次。
- **可诊断**：错误应指出来源和修复方向，避免堆栈噪音。
- **稳步推进**：每个语言能力都应沿解析、语义、后端和回归形成闭环。

## 语法基线

源码扩展名为 .lcy。使用花括号表示块，缩进不参与语义；普通语句的分号可选。条件分支和循环的条件括号可选；计数循环允许省略循环头分号，语法必须能够明确区分初始化、条件和更新部分。

函数、参数和显式变量均采用类型在前的声明。类型推导只决定静态类型，不使变量成为动态值。类型后的问号表示可空类型，不表示错误传播。

逻辑与、逻辑或按从左到右的短路规则求值；仅在左侧不能确定结果时执行右侧。短路不会放宽静态名称和类型检查。

```lency
int add(int left, int right) {
    return left + right
}

int main() {
    int values[3] = {1, 2, 3}
    vec<int> pending = vec[]
    for (int i = 0; i < 3; i = i + 1) {
        pending.push(values[i])
    }
    return add(pending[0], pending[1]) - 3
}
```

固定数组使用名称后的维度和花括号初始化。动态集合类型使用小写名称；动态字面量当前保留已有形式，其初始化语法不由固定数组的修改自动决定。

组合导入在共享的模块前缀后列出子模块：

```text
import std.{io, fs, str}
```

类型组织使用结构体和组合，通过实现块定义方法。不提供继承，不因嵌入字段而隐式提升成员或转发方法。

泛型调用使用函数名后的普通尖括号；不采用 Rust 风格的路径分隔调用、宏式集合字面量或闭包写法。分支箭头仅用于匹配。

## 错误处理

能在编译期确定的类型、名称和语法错误直接拒绝编译。运行时发现除零、越界、非法空值访问或明确的不可恢复错误时，通过 panic 报告信息并终止程序。主动报告使用普通函数调用形式：

```text
panic("配置文件不存在：" + path)
```

panic 不返回、不可捕获、不可恢复，不要求函数签名附加错误类型或统一结果包装。不提供失败语句、隐式或显式错误传播操作符、调用处错误捕获块。诊断需要提供原因和可用的源码位置；完整调用栈由实现能力决定，不能把本机回溯等同于已完成源码级调用栈。

查询没有找到等正常业务结果可以用可空值或普通业务数据表达，但不能用哨兵值隐藏应触发 panic 的错误。用户枚举及其项没有名称特权，不内建统一结果包装。

强静态不等于禁止类型转换。转换范围和失败行为必须由明确规则约束，不得把当前实现的数值转换偏差直接固化为语言规则。

命名约定使用大驼峰类型名、小写下划线函数和变量名；内建动态集合类型使用明确的小写拼写。

编译器可以具有集中、可测试的运行时原语，但它们的名称、类型和调用契约必须明确；普通调用语法不意味着依赖名称碰巧相同的用户声明即可获得特殊语义。

示例：

```lency
int add(int left, int right) {
    return left + right
}

int main() {
    var result = add(1, 2)
    print(result)
    return 0
}
```

程序错误不进入函数签名：

```lency
int divide(int left, int right) {
    return left / right
}
```

当 `right` 为 `0`，运行时必须终止并报告整数除零，而不是返回哨兵值、抛出可捕获异常或构造 `Result`。调用者无需为程序错误编写与正常控制流混杂的传播代码。

正常查询可以返回没有值，而无需把它定义为程序错误：

```text
int? find_index(string text, string needle)
```

可空类型用于明确的业务缺失。普通用户枚举也可以表达业务分类，但不具有统一错误包装或自动传播语义。

## 实现边界

Rust 母体编译器和 Lency 自举编译器共享语言方向，但不是两个并行竞争的主线：

- Rust 母体是稳定的 stage0、参考实现和自举支撑。
- Lency 自举编译器是当前主线，先追求最小且可收敛的自举子集。
- 目标语法、Rust 母体能力和 selfhost 能力必须分开描述，不能使用一个“完成百分比”混在一起。

新增语言特性前，应先回答：

1. 是否让程序含义更清晰？
2. 能否用 Lency 自举实现，而不依赖大量特殊分支？
3. 能否用一个最小正例和一个最小负例定义其边界？

如果答案不明确，先不加入语言。
