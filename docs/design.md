# Lency 设计原则

## 定位

Lency 是一门面向日常程序开发的静态类型语言。它追求 C 系语言清晰的块结构和接近脚本语言的表达效率，但不以替代 C、C++ 或 Rust 的底层能力为目标。

最终目标是自举：使用 Lency 实现并构建 Lency 编译器。

## 核心原则

- **清晰**：语义应能从源码直接理解，拒绝要求读者模拟编译器推理的“黑魔法”。
- **显式**：避免隐式转换和不可解释的泛型推断；重要边界应出现在语法中。
- **默认安全**：空值必须显式进入类型，尽量在编译期阻止错误。
- **简洁**：避免 Java 式样板和无收益的抽象层级。
- **组合优先**：优先使用结构体、trait 和组合，而不是继承层次。
- **可诊断**：错误应指出来源和修复方向，避免堆栈噪音。
- **稳步推进**：每个语言能力都应沿解析、语义、后端和回归形成闭环。

## 语法基线

- 源文件扩展名为 `.lcy`。
- 使用 `{}` 表示块；格式化缩进是风格要求，不参与语义。
- 函数签名使用 `返回类型 函数名(类型 参数)`，不在参数列表后追加错误类型、效果或异常声明。
- 显式局部变量使用 `类型 名称 = 值`；`var 名称 = 值` 只表示强静态类型推导，不接受 `var 名称: 类型`。
- 泛型调用写作 `identity<int>(value)`，不接受 Rust 的 `identity::<int>(value)`。
- 动态数组字面量写作 `vec[1, 2, 3]`，不使用 `vec!`；固定数组类型写作 `int[3]`。
- `=>` 只用于 `match` 分支，不提供 `|参数| => 表达式` 闭包语法。
- 类型静态确定；`T?` 表示可空类型。
- 程序错误（如整数除零、越界、空引用和不可恢复的不变量破坏）立即 `panic`；普通函数不为这些错误改变返回类型。
- 不提供异常式 `try-catch`，不提供 `T!` 返回类型糖，也不提供后缀 `?` 隐式传播。
- 错误没有独立于返回值的隐藏通道。可恢复结果必须作为普通数据进入函数返回值和正常控制流。
- 不内建 `Result`、`Ok` 或 `Err`。不需要失败原因的“可能没有值”使用 `T?`；需要区分多种可恢复结果时，由 API 声明普通 enum，并由调用者使用 `match` 处理。
- 命名约定：类型使用 `PascalCase`，函数和变量使用 `snake_case`，常量使用 `SCREAMING_SNAKE_CASE`。

“没有黑魔法”不等于编译器没有原语。整数运算、内存、`Vec` 布局和少量 runtime intrinsic 必然有实现边界，但必须满足：名称和类型契约有文档、调用在语法层使用普通 `Call` AST、原语以全局函数符号参与名称和类型检查、lowering 集中且可测试。原语名称不是词法关键字，但当前不允许由用户重复声明。编译器不得根据用户类型或枚举项恰好叫 `Result`、`Option`、`Ok`、`Err` 就改变语义。

示例：

```lency
int add(int left, int right) {
    return left + right
}

int main() {
    var result = add(1, 2)
    print(result)
    return 0
}
```

程序错误不进入函数签名：

```lency
int divide(int left, int right) {
    return left / right
}
```

当 `right` 为 `0`，运行时必须终止并报告整数除零，而不是返回哨兵值、抛出可捕获异常或构造 `Result`。调用者无需为程序错误编写与正常控制流混杂的传播代码。

可恢复失败也不改变函数声明的 C 系外形。例如文件读取 API 可以返回自己声明的普通 enum：

```lency
enum ReadOutcome {
    Content(string),
    Failure(Error)
}

ReadOutcome read_text(string path) {
    // 实现返回普通 enum 数据；没有异常或隐式传播通道
}
```

`ReadOutcome`、`Content` 和 `Failure` 都没有编译器特权。项目也可以自行声明名为 `Result`、`Ok`、`Err` 的类型或枚举项，它们仍只是普通用户代码。

## 实现边界

Rust 母体编译器和 Lency 自举编译器共享语言方向，但不是两个并行竞争的主线：

- Rust 母体是稳定的 stage0、参考实现和自举支撑。
- Lency 自举编译器是当前主线，先追求最小且可收敛的自举子集。
- 目标语法、Rust 母体能力和 selfhost 能力必须分开描述，不能使用一个“完成百分比”混在一起。

新增语言特性前，应先回答：

1. 是否让程序含义更清晰？
2. 能否用 Lency 自举实现，而不依赖大量特殊分支？
3. 能否用一个最小正例和一个最小负例定义其边界？

如果答案不明确，先不加入语言。
