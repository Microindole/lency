# Rust 母体固化基线

Rust 母体承担固定 stage0、普通程序参考实现及混合自举后端支撑。固化对象是下列可执行基础能力，不以语言功能大而全或两套编译器完全等价为要求。

## 基础能力

| 范围 | 固化契约与验收 |
|---|---|
| 语法 | 类型在前的函数及变量声明、花括号块、可选条件括号、可选计数循环括号及完整三段间分号、C 风格固定数组、模块组合导入 |
| 控制流 | 条件分支、短路、循环、嵌套、跳转、作用域恢复与返回路径；验证实际执行次数和顺序 |
| 函数 | 普通调用、前向引用、递归、相互递归、跨模块调用及参数和返回值类型检查 |
| 数据 | 数值、布尔、字符串、固定数组、动态集合、结构体组合、实现块方法、枚举与穷尽匹配、可空值、已有泛型函数及结构体实例化 |
| 内存 | 手动浅层释放，匹配分配器；已有引用赋值及传参不自动深拷贝，不自动转移归属；标准字符串与 I/O 包装遵循明确的返回归属 |
| 错误 | 整数除零、余数除零、除法溢出、越界、空集合弹出、转换失败、非法释放及主动 panic 终止程序；不通过默认值伪造成功 |
| 诊断 | 母体源码路径登记函数、方法与文件行列；跨文件递归、方法及间接调用具有调用栈回归；导入模块的语义错误使用原始文件位置 |
| 构建 | 普通与优化生成代码分别运行；自举 stage2 和 stage3 的编译器及样例 LIR 收敛 |

源码中的循环、递归和可变状态必须实际运行正确，不能仅凭语法接受、生成了 IR 或成功构建编译器自身判定基础功能可用。

无值结果不能声明为变量或传给打印入口；没有类型上下文的空值和空集合必须补充类型注解，不能由后端猜测具体类型。

## 固定边界

- 不新增继承、闭包、宏、隐式错误传播、捕获恢复或统一结果包装。
- 不引入 GC 或引用计数，不承诺手动管理下的完整内存安全；释放后使用和裸地址复用后的旧别名属于调用者责任。
- HashMap 整数句柄是兼容 ABI，必须使用对应构造和释放入口，不等价于任意整数都具有容器语义。完整强类型泛型容器抽象不属于此基线。
- 当前不支持的复杂调用目标、函数名或类型名作为普通结果值必须明确拒绝，不能使用错误占位类型使检查成功。已有外部函数类型调用另有回归。
- 字符串索引是 UTF-8 字节索引；大小写转换仅处理 ASCII，字节反转不等于 Unicode 字素反转。
- 自举 LIR 的源码元数据及独立后端属于自举实现职责，不能把母体 AST 源码路径的能力直接当作自举能力。
- 跨平台结果以对应平台执行同一验收入口为准，本地通过不代替其他架构的 CI 运行。

这些边界限定当前基础子集，不允许将该子集中的实现回归重新解释为“不支持”。

## 必须保留的检查

```powershell
cargo run -p xtask -- stage0-check
cargo run -p xtask -- auto-check
cargo run -p xtask -- bootstrap-check
```

stage0-check 构建 release 母体和 runtime，将控制流、数据、标准库、文件及错误用例分别编译为普通和优化程序。它核对退出码、输出、源码帧与手动分配余额；语义负例还核对具体诊断，子进程超时直接失败。源码夹具位于 tests/stage0，生成程序和日志位于 target/stage0_check。

Rust 检查直接包含该入口，标准库或验收夹具变更也会触发 Rust 检查。源级间接调用、语法边界及底层容器行为由对应 crate 回归补充。

后续以 Lency 自举编译器为主线。Rust 母体只接受基线回归修复、平台兼容修复及自举直接需要的过渡支撑，不继续无边界扩展语言特性。
