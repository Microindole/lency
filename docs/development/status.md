# 自举状态

## 当前阶段

项目处于混合自举阶段。Lency 自举编译器负责读取源码、语法与语义检查、发射项目 LIR；Rust 母体负责将 LIR 转为 LLVM 并完成构建和链接，runtime 仍由 Rust 实现提供。

阶段检查覆盖编译器 LIR、样例 LIR 和运行结果的收敛。LIR 收敛表示当前输入和工具链下输出一致，不等于完整功能等价，也不等于已经具备独立后端。

当前开发主线是自举编译器。Rust 母体承担已确认语法要求的对齐和参考行为缺陷修复，普通程序仍以母体作为默认编译入口；母体修改不作为继续扩展未定稿语言能力的理由。

## 可验证的范围

现有回归覆盖编译器自身使用的基础表达式、函数、控制流、字符串、Vec、模块签名，以及非泛型结构体、方法、枚举匹配的运行子集。语法可解析、语义可检查和端到端可运行是三个不同层级。

语法写法和两套前端的差异见[基础语法](../basics/syntax.md)。函数、返回、条件与集合的具体规则分别在[函数](../basics/functions.md)、[控制流](../basics/control-flow.md)和[Vec](../stdlib/vec.md)中说明。

母体逻辑运算的运行回归覆盖短路求值、操作数执行顺序与次数，以及嵌套表达式和边界检查的配合。运行时跳过的操作数仍接受完整的静态检查。

母体的成员赋值回归覆盖接收者单次求值、非空检查后的可空结构体读写及结构体空值合并；非法赋值目标在语义检查阶段拒绝。可空标量回归覆盖零和假、赋值、参数和返回值、字段及安全导航、按值比较、可空元素集合和惰性空值合并；不代表所有容器与泛型组合已经完整验证。

## 当前阻塞

- 自举编译器尚无独立的 LLVM 或本机代码后端，阶段构建仍依赖 Rust 母体。
- 泛型实例化、完整方法与 trait 体系、完整标准库尚未形成稳定的自举运行子集。
- 两套前端仍有语法接受范围差异，不能直接互换所有测试输入。
- 母体接受可选括号与分号的计数循环、C 风格固定数组声明、小写集合类型和模块前缀组合导入；自举前端尚需对齐这些完整形式。旧类型拼写与数组声明保留兼容入口供现有源码使用，不能当成新的公开语法方向。
- 母体 panic 诊断统一输出到标准错误并以非零状态退出，主动调用保留源行号；当前只有可用本机回溯，原始多文件定位和完整 Lency 调用栈仍需完善。
- 母体结构体与可空值单元沿用堆分配，统一的对象生命周期和自动回收尚未实现。
- 部分类型传播和中间表示仍存在兼容路径，需要由具体失败用例确认并收紧。

后续能力以编译器自身的数据结构、控制流和独立构建需要为准。实现差异属于待处理边界，不作为修改语言设计的依据。

## 验证入口

```powershell
cargo run -p xtask -- check-lency
cargo run -p xtask -- bootstrap-check
```

具体命令和环境配置见[工具与脚本](../tools/scripts.md)，阶段职责见[自举路线](./bootstrap.md)。运行回归位于 tests/example/runtime，语法与语义回归位于 tests/example/selfhost。本文只描述当前自举状态；逐次修改记录由 Git 历史承担。
